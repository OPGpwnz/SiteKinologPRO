РОЛЬ И КОНТЕКСТ

Ты — Senior Full-Stack разработчик. Твоя задача — спроектировать и написать код для сайта PITFLY (физподготовка собак: стаффорды, питбули, служебные породы). Тренер один.
Стек: Next.js (App Router), TypeScript, Tailwind CSS, Supabase (PostgreSQL, Auth, RLS), Vercel.

1. СТРУКТУРА САЙТА И UI (Визуал)

· Стиль: Брутальный, спортивная агрессия. Темный хром, металлик. Фон: #0A0A0A и #1A1A1A. Поверхности: #2A2A2E.
· Акценты: Ледяной голубой (основные кнопки, активные элементы). Кислотно-зеленый (только для точечных статусов: «оплачено», «свободно»). Запрещены светлые, пастельные и «зализанные» дизайны.
· Типографика: Широкие агрессивные гротески для заголовков (Druk, Unbounded, Bebas Neue), Manrope для текста. Цены — крупные, как на табло. Резкие углы (радиус 0–4px).
· Графика: Только реалистичные иллюстрации (не фото) мускулистых собак в движении. Логотип: надпись PITFLY в окружности (в хроме).
· Страницы: Главная (с блоком «Индивидуальный подход», без текстов «О тренере» и списка программ), Прайс, Личный кабинет клиента, Админка тренера.

2. БАЗА ДАННЫХ (Supabase / PostgreSQL)

Создай SQL-миграции для следующих таблиц:

2.1. profiles

· id (uuid, PK, ссылается на auth.users)
· email (text, unique)
· phone (text)
· role (text, default 'client') — client или trainer.
· notify_email (boolean, default true), notify_sms (boolean, default false), notify_telegram (boolean, default false) — настройки уведомлений клиента.

2.2. services (Справочник услуг, заполняется сидом)

· id (smallint, PK), code (text, unique), title (text), price (int), duration_min (int), category (text), requires_pair (bool), is_subscription (bool).
· Сид-данные:
  · trial (Первая тренировка) — 1000₽, 60 мин.
  · single_60 (Разовая с тренером) — 1800₽, 60 мин.
  · single_40 (Разовая для щенков/мелких пород) — 1800₽, 40 мин.
  · subscription (Абонемент 5 занятий) — 7500₽, 60 мин.
  · pair (Парная тренировка) — 1000₽ (с каждого), 60 мин, requires_pair = true.
  · rent_equipment (Аренда со снарядами) — 800₽, 60 мин.
  · rent_plain (Аренда без снарядов) — 500₽, 60 мин.
  · rent_day_plain (Полный день без снарядов) — 5000₽, 720 мин.
  · rent_day_equipment (Полный день со снарядами) — 8000₽, 720 мин.
  · treadmill_30 (Дорожка 30 мин) — 500₽, 30 мин.
  · treadmill_60 (Дорожка 60 мин) — 1000₽, 60 мин.

2.3. slots (Доступные слоты)

· id (uuid), trainer_id (uuid), starts_at (timestamptz), ends_at (timestamptz), capacity (smallint, default 1 — для парных = 2), is_open (boolean).

2.4. bookings (Записи)

· id (uuid), slot_id (uuid), client_id (uuid), service_code (text), pair_group_id (uuid, nullable), status (text: active/cancelled/completed/no_show), payment_status (text: unpaid/paid), subscription_id (uuid, nullable).

2.5. subscriptions (Абонементы)

· id (uuid), client_id (uuid), total_lessons (smallint, default 5), used_lessons (smallint, default 0), expires_at (timestamptz, +45 дней от покупки), status (text: active/expired/used_up).

(Настрой RLS: клиенты видят только свои записи/абонементы; тренер видит всё).

3. АВТОРИЗАЦИЯ И БЕЗОПАСНОСТЬ

· Вход и регистрация по email и паролю через Supabase Auth; новые профили получают роль client.
· Сессия живет 90 дней (настроить JWT expiry и refresh token).
· Клиенты не могут видеть чужие данные (RLS политики).
· Тренер получает роль trainer вручную в БД.

4. БИЗНЕС-ЛОГИКА И API

4.1. Запись и Слоты

· Создание слотов: Тренер в админке может создавать как одиночные слоты, так и шаблоны (recurring) (например, «Вторник с 10 до 18»), которые пачкой генерируют слоты на месяц вперед.
· Обычная запись: 1 клиент на слот. Парная запись (pair): Клиент А создает бронь, получает pair_group_id. Клиент Б бронирует тот же слот, ему присваивается тот же pair_group_id. Если один отменяет — второй остается, а в админку летит уведомление, что пара распалась.
· Отмена: Разрешена не позднее чем за 5 часов до starts_at. Если позже — API возвращает ошибку 403, клиент видит сообщение «Свяжитесь с тренером».

4.2. Абонементы

· При записи клиент выбирает: оплатить разово или списать с абонемента (если есть активный и не истекший).
· Срок действия: 1,5 месяца (45 дней). По истечении cron-задача ставит статус expired.
· Важно: Тренер в админке может нажать «Продлить», что добавит 45 дней к expires_at и вернет статус active.

4.3. Уведомления

· Клиент управляет подписками в ЛК (Email, SMS, Telegram). Отправка только по тем каналам, где стоит true.
· Тренер получает уведомления о новых записях (Email по умолчанию).
· Настроить Supabase Edge Functions для отправки (используй Resend для Email, API Telegram-бота, Twilio/SMS.ru для SMS).

5. АДМИН-ПАНЕЛЬ (Для тренера)

· Календарь: Визуальное отображение слотов. Возможность закрыть конкретный слот (is_open = false).
· Список записей: Кто придет, на какую услугу (видно, что выбрана тренировка 40 мин для щенка), кнопка «Отметить оплату» (меняет payment_status на paid).
· Клиенты: Список, история, кнопка «Выдать абонемент».
· Абонементы: Список всех, кнопка «Продлить».

6. ЭНДПОИНТЫ (Next.js API Routes)

· GET /api/services — список услуг.
· GET /api/slots — получение свободных слотов (фильтр по дате, только is_open=true и не в прошлом, учет capacity).
· POST /api/bookings — создание записи (транзакция с проверкой свободных мест).
· PATCH /api/bookings/:id/cancel — отмена (проверка правила 5 часов).
· GET /api/client/dashboard — данные для ЛК (записи, абонементы).
· POST /api/admin/slots/bulk — создание сетки слотов.
· PATCH /api/admin/subscriptions/:id/extend — продление.
